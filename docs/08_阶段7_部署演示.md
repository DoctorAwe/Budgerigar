# 阶段 7：Colab、Gradio 与交付

Colab 是本项目唯一的真实验证环境，不只是最终展示入口。阶段 1 起的真实数据流程、阶段 2–6 的训练评估以及阶段 7 的演示验收都通过 notebook 执行。

## Colab 文档结构

最终提供两个 notebook，避免训练依赖与轻量演示互相污染。

### `Budgerigar_Train.ipynb`

1. 检查 GPU、CUDA、磁盘和 Drive。
2. 安装固定版本依赖并打印环境摘要。
3. 挂载 Drive；下载公开数据时展示许可提示。
4. 构建 manifest、运行小样本数据审计。
5. 选择 `smoke_test`、`baseline` 或 `streaming_finetune` 配置。
6. 训练、定期保存到 Drive、支持断点恢复。
7. 在 golden set 上计算指标并导出音频。
8. 导出仅推理 checkpoint、配置和模型卡。

每次真实实验还必须保存 `run_metadata.json`，至少包含 Colab runtime、GPU 型号、CUDA/PyTorch 版本、git commit、数据 manifest hash、配置、随机种子、开始/结束时间和最终指标。

Colab 免费 GPU 会回收会话，因此每个 epoch/固定 steps 保存可恢复 checkpoint；下载数据和特征缓存必须幂等。

### `Budgerigar_Demo.ipynb`

1. 安装最小推理依赖。
2. 从 Drive、Release 或手动上传加载 checkpoint。
3. 校验 checkpoint hash 与配置版本。
4. 运行一条离线样例和流式一致性测试。
5. 启动 Gradio；打印本地与临时分享链接。

## Gradio 页面

页面分为两种模式：

- 文件模式：上传/录制整段音频，便于质量对比和下载。
- 实时模式：麦克风分块输入，播放器连续输出，并显示当前缓冲与延迟。

控件只暴露安全、明确的参数：输入设备、韵律档位、降噪开关、chunk/look-ahead 预设、重置会话。目标音色固定，不提供上传任意目标人声进行克隆的入口。

状态面板显示：

- 输入/输出波形；
- 当前 RTF、首包和 P95 chunk 延迟；
- VAD、削波、低 SNR 警告；
- 当前模型与配置版本。

## Gradio 流式注意事项

- 浏览器麦克风块大小不稳定，服务端必须重分块。
- 每个浏览器 session 独立保存模型状态并设置超时清理。
- 音频输出用连续序号避免乱序；丢包时插入平滑静音。
- GPU 推理用有界队列；过载时提示降级，不能无限堆积延迟。
- 分享链接只用于临时演示，不视为生产部署。

模型卡必须记录训练数据、授权、适用语言、已知失败模式、身份泄漏评估、延迟硬件和禁止用途。

## 验收流程

1. 在全新 Colab 会话运行训练 smoke test。
2. 重启 runtime 后从 checkpoint 恢复。
3. 在全新会话仅运行 Demo notebook。
4. 文件模式、麦克风模式、reset 和长静音均测试。
5. 录制 10 分钟性能日志，确认显存/内存无持续增长。
6. 将 notebook 输出清理后提交，但保留预期结果截图和指标说明。
7. 只接受 Colab 生成的数据审计、音频样例、指标和性能日志作为阶段验收证据。

## 阶段退出条件

- 新用户按文档无需修改代码即可完成 smoke test 和推理。
- checkpoint 下载可校验且与配置绑定。
- Gradio 连续运行 10 分钟无状态串线、内存增长或明显断音。
- README、Colab、模型卡中的命令和版本保持一致。
