# 项目路线图

## 1. 产品定义

Budgerigar 是一个实时 any-to-one 语音转换系统：输入可以来自未见过的说话人，输出始终采用预先定义并授权使用的 Budgerigar 目标音色。模型复述语句内容，保留可懂度和大致时序，但由模型决定最终音高区间、音色、能量风格和细微语调。

模型行为遵循现实中的复读：先听取一个完整表达，再按照自己的音色、语气和人格复述，而不是同步变声。句子是否已经完整、何时值得开始复述，不由外部 `LISTEN/END/READ` 状态机硬编码；网络在连续音频时间轴上通过自身隐状态学习保持静默、积累内容和开始输出。

第一版不追求跨语言翻译、多人分离、歌声转换或完全零延迟。输入中出现音乐、重叠说话、强噪声时允许拒绝或降级。

## 运行与验证环境

- 本地：编写代码、类型/语法检查、使用合成小样本进行轻量单元测试。
- Colab：下载 ESD/CMU ARCTIC、生成真实 manifest、提取特征、GPU 训练、断点恢复、客观/主观音频评测和 Gradio 演示。
- 所有质量、显存、RTF 和延迟结论必须来自记录了 Colab GPU 型号与运行配置的实验；本地冒烟测试不计入模型验收。
- 数据集不提交到仓库，也不要求本地工作区持有副本。

## 2. 总体架构

```text
16/24 kHz 连续音频流
  -> 响度/质量特征（VAD 仅作为输入特征，不充当控制器）
  -> 因果内容编码器（尽量去除说话人身份）
  -> 多时间尺度层级记忆
  -> 学得的完整性/输出意愿隐变量
  -> 固定目标音色 + 模型自身韵律与人格
  -> 连续声学输出（听取期间学习输出静默，完整后复述）
  -> 流式声码器
```

采用“双轨特征”：内容分支承载音素/语义，韵律分支只保留时长、重音和句型等低带宽信息。目标说话人嵌入固定，避免把输入身份复制到输出。

## 4. MVP 技术选择

- 音频：24 kHz 单声道；10 ms hop；20–40 ms 输入 tick。
- 内容编码：预训练语音表征的冻结或轻量微调版本，加说话人对抗头。
- 声学目标：80/100 维 log-Mel，便于训练与诊断。
- 解码：因果卷积 + 小型 GRU/状态空间块。
- 声码器：支持因果卷积的轻量神经声码器。
- 目标音色：只使用获得授权的真人录音，或明确许可的合成音色。

神经 codec token 作为第二路线；只有当 Mel 基线证明内容—身份解耦后才引入，以免同时调试量化、码本坍缩和流式生成。

## 5. 关键风险

- 平行数据规模小：用平行样本建立映射，用大规模非平行数据增强内容鲁棒性。
- 输入音色泄漏：身份对抗损失、目标嵌入固定、说话人相似度审计。
- 训练/流式不一致：训练时显式维护状态并随机切块，禁止未来帧。
- 声码器边界爆音：固定感受野、状态复用和 overlap-add。
- “自己语调”定义含糊：将其定义为目标语料的 F0/能量先验与可学习风格 token，不直接复制输入绝对 F0。
