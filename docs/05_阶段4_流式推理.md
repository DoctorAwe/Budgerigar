# 阶段 4：流式模型与实时推理

## 因果约束

训练和推理都只能访问当前及过去 tick。所有卷积使用左侧 padding；归一化不能读取整句统计；注意力使用因果 mask；F0 标准化采用滑动在线统计。

允许一个可配置的小型 look-ahead（例如 40–80 ms），但必须计入算法延迟，且存在零 look-ahead 对照。

## 流式接口

```python
state = model.start_session(sample_rate=24000)
for pcm_chunk in input_stream:
    output_chunk, state, metrics = model.process_chunk(pcm_chunk, state)
tail = model.flush(state)
```

`process_chunk` 必须接受不规则设备分块，内部通过 ring buffer 整理成固定 tick。模型状态、声码器状态、重采样状态和 overlap-add 尾部都属于 session，不能使用进程级全局变量。

## 音频时序

推荐初始配置：

- 设备输入块：10–20 ms；
- 模型 tick：20–40 ms；
- 可选 look-ahead：40 ms；
- 声码器输出块：20–40 ms；
- 播放 jitter buffer：40–80 ms。

端到端延迟应实测：`采集缓冲 + 重采样 + look-ahead + 模型计算 + 声码器 + 播放缓冲`，不能只报告神经网络耗时。

## 训练—推理一致性

- 从长音频随机切成连续 chunks，跨 chunk 传递真实状态。
- 随机改变 chunk 大小、插入静音和 missing mask。
- truncated BPTT 每隔若干 chunk 截断梯度，但不清空状态。
- 同一音频做整段因果推理和流式推理，比较 Mel 与波形差异。

## 工程优化顺序

1. PyTorch eager 正确性版本。
2. 分模块 profile，定位 encoder、decoder、vocoder 占比。
3. 混合精度和缓存复用。
4. `torch.compile` 或 ONNX 导出；验证状态张量的动态 batch/chunk。
5. 量化只在质量基线稳定后进行。

## 退出条件

- 目标 GPU 上 RTF `< 0.5`，连续 10 分钟无缓存增长。
- 首包算法延迟 `< 300 ms`，并提供分项测量。
- 任意 chunk 边界无明显爆音；flush 不截断尾音。
- 并发 session 状态隔离；reset 后结果可复现。
